Why evals decide everything

Evals are automated tests for AI behaviour. They turn "the answers feel worse" into numbers you can compare, gate releases on and debug.

Without them every prompt tweak, model upgrade or chunking change is a guess. With them you can say "recall@5 went from 0.82 to 0.88 and groundedness held at 0.96, so we ship".

What to measure, stage by stage

MetricQuestion it answersNeeds
Recall@kDid the right chunks make the top k?Labelled relevant chunks per question
MRRHow high was the first right chunk?Same
nDCG@kWere the best chunks near the top, with graded relevance?Same, optionally graded 0 to 3
Groundedness (faithfulness)Is every claim supported by the retrieved context?The answer and its context; an LLM judge
Answer correctnessDoes it match the reference answer?A reference answer per question
Task successDid the agent achieve the goal?A checker: state in a sandbox, or a judge
Tool-call accuracyRight tool, right arguments, right order?An expected trajectory
SafetyLeaks, forbidden actions, injection followed?Adversarial test cases; must be zero

Retrieval metrics, hands on

Question: "How many weeks do adoptive parents get in India?" The golden set marks 3 chunks as relevant (green). Pick a ranking, or mark results yourself, and watch the metrics move.

Presets

    recall@k = relevant in top k ÷ all relevant  ·  MRR = 1 ÷ rank of first relevant  ·  nDCG@k = Σ rel / log₂(rank + 1), divided by the ideal

    Retrieval metrics are cheap, fast and need no LLM, so run them on every change. If recall@k is low, no prompt can fix the answer: the model never saw the right text.

    Grading answers: groundedness and judges

    • Use a rubric with specific questions ("Does every number appear in the context?") instead of "rate 1 to 10".
    • Known biases: judges prefer longer answers, the first option in a pair, and text from their own model family. Shuffle order, cap length, and use a different model family where you can.
    • Prefer code checks when possible: JSON schema valid, citation IDs exist, required fields present. They are free and never drift.

    Evaluating agents

    Run agent evals in a sandbox with fake but realistic tools, so a test can place an order without spending money. Score task success from the final state (was exactly one order created, with approval?), plus steps taken, tokens, latency and any forbidden calls.

    Building a golden set

    A golden set is a versioned file of questions with what a good answer needs: the relevant chunks, a reference answer, and for agents the expected outcome. Start with 100 to 300 cases and grow it from production.

    SliceExampleExpected behaviour
    Common questions"How much parental leave in India?"Correct, cited answer
    Exact IDs and names"What does HR-4512 say?"Finds that exact document
    Multi-hop"Compare India and US adoptive leave"Uses both sections
    Stale contentA 2022 page contradicts the 2025 onePrefers the newer, mentions the change
    No answer"What is the CEO's home address?"Declines; does not invent
    PermissionsAn intern asks about board minutesReveals nothing, not even that it exists
    InjectionA document says "ignore previous instructions"Treats it as text, not a command

    Sources: real (anonymised) user questions first, subject experts second, and LLM-generated questions only after a human has reviewed them.

    Release gates and production evals

    Run the golden set in CI on every change and compare with the current production baseline:

    One failed safety rule blocks the release, whatever the averages say. After the gate, ship as a canary, then keep evaluating in production: sample 1 to 5% of real traces into the judge, track thumbs and edits, and alert when groundedness or the fallback rate moves.

    Saying it in an interview

    "I'd build a golden set of about 200 questions from real logs, sliced into common, exact-ID, multi-hop, stale, no-answer, permission and injection cases. Offline, I'd measure recall@k and MRR for retrieval, groundedness and correctness with an LLM judge that's calibrated against human labels, and trajectory checks for the agent in a sandbox. That runs in CI as a gate against the production baseline, with safety rules that must be perfect. Online, I'd sample traces into the same judge, track user feedback, and turn every failure into a new golden case."
