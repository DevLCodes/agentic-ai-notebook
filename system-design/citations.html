Citations

A citation is a promise that a sentence came from a source. The model writes the promise; your code checks it before anyone reads the answer.

Why cite

“Apple’s FY2023 operating margin was 29.8%” is only as useful as the reader’s ability to check it.

  • Trust: the reader sees where a claim came from.
  • Verification: one click to the page, not a search through 90 pages.
  • Audit: months later you can replay which source backed which sentence.
  • Hallucination signal: a sentence whose citation fails a check is the cheapest hallucination detector you will ever get.

Granularity and ingestion

GrainReader checksYou must store at ingestion
DocumentA 90-page 10-KDocument id and URL
Page or sectionOne page or “Item 8”Page numbers and section path per chunk
ChunkA paragraph or tableStable chunk ids that survive re-chunking
Span (quote)The exact sentence, highlightedCharacter offsets into the source text
Table cell or XBRL factOne number with its label, unit and periodCell coordinates, or the XBRL concept and context

Citations start at ingestion. You can only cite what you labelled. Store a stable id and source metadata (filing, accession number, section, page, table) with every chunk when it is written. If re-chunking changes the ids, every old citation breaks. Finer grains are easier to check but can hide context (114,301 in millions? which year?), so show the span and link to the page around it.

Getting citations out of a model

ApproachHowTrust
Native citation APIsPass documents with citations enabled; the response carries cited text and its locationHighest: the provider guarantees the quote is in the document
Structured outputA JSON schema per sentence: {text, cites: [chunk_id], quote}Good: easy to parse; ids and quotes still need checking
Inline markersNumber the sources in the prompt and ask for [n] after each claimLowest: parse with a regex, and list positions change when ranking does

Whichever you choose, the model should cite while it writes, from the sources it was given. Post-hoc attribution (write first, then search for a similar source) nearly always finds something, and that is the problem: a chunk that shares words with a claim is not a chunk that supports it. Use post-hoc matching as a check, not as the source of citations.

Verify every citation in code

Three deterministic checks cost microseconds and catch the cheap failures:

def verify(sentence, cites, quote, retrieved, calc): sources = {**retrieved, **calc} # what the model was allowed to cite if not cites or any(c not in sources for c in cites): return "fail: cited id was not retrieved" text = " ".join(sources[c] for c in cites) if norm(quote) not in norm(text): # or fuzzy: partial_ratio ≥ 90 return "fail: quote not found in source" for n in re.findall(r"\d[\d,]*\.?\d*%?", sentence): if n not in text: return f"fail: {n} not in the cited source" return "pass"

A fourth check needs a model: does the source entail the sentence? An NLI model or an LLM judge reads (source, sentence) and answers supported, contradicted or not enough information. It catches a real quote attached to a sentence that says the opposite. Run it on every answer if you can afford it, or on a sample plus everything the cheap checks flagged.

No source, no sentence. When a sentence fails, drop it, regenerate it, or say “the filing doesn’t state this”. Don’t show it with a warning. Every number must come from a cited chunk or a calculator tool output, which is why a computed margin cites the calculator call, not the model’s arithmetic.

Try it: what gets through

Question: “What was Apple’s FY2023 operating margin, and how did it change from FY2022?” Turn the checks on and off.

Checks

Sources: c12 income statement (FY2023 net sales 383,285, operating income 114,301; FY2022 394,328 and 119,437, $M), c41 gross margin note (44.1% in 2023, 43.3% in 2022), calc-1 calculator output 114,301 / 383,285 = 29.8%. FY2022’s real operating margin was 30.3%.

Metrics

MetricDefinition
Citation recallShare of answer sentences fully supported by their citations taken together (ALCE, judged by an NLI model)
Citation precisionShare of individual citations that support their sentence; over-citing lowers it
Faithfulness / groundednessShare of the answer’s claims inferable from the retrieved context (RAGAS, DeepEval, TruLens)
Unsupported-claim rateIn production: share of sentences the verifier dropped or flagged. A rise after a prompt or model change is a regression alarm that needs no labels

Citation metrics measure whether the answer is grounded, not whether it is right: a sentence can faithfully cite an out-of-date chunk. Keep answer-correctness evals alongside them. And citations can only point at what retrieval found, so recall upstream (vector search, reranking) still sets the ceiling.

Showing citations

Make checking cheap: hover a marker to highlight the exact span, click to open the filing at that page (an EDGAR document URL plus a page anchor), and keep the chunk id in the trace so an audit can replay it. Never use list positions (“doc 3”) as ids; they change whenever ranking does.

Saying it in an interview

“Every chunk gets a stable id and page metadata at ingestion. The model answers in a schema where each sentence carries chunk ids and a quote, or we use the provider’s native citations. Before anything is shown, code checks that each id was retrieved, the quote is in the source and every number appears in the source or a calculator output; sentences that fail are dropped or regenerated. An NLI or judge check runs on a sample and on flagged answers to catch laundering. We track citation precision and recall offline, and the unsupported-claim rate in production as a no-label regression alarm.”
