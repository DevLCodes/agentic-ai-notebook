Memorise these first

If you remember only twelve, remember these. In an interview, name the metric, give one target number, and say how you would measure it.

  1. Recall@5: retrieval found the evidence
  2. Groundedness: claims supported by sources
  3. Task success + argument accuracy: agents did the right thing
  4. Per-class precision/recall + macro-F1: classifiers on imbalanced data
  5. Execution accuracy: text-to-SQL
  6. Faithfulness + coverage: summaries
  7. p95 latency + cost per request: operations
  8. Zero leaks on the red-team/permission suite: safety
  9. No slice regresses > 1 point: release gate
  10. One primary metric + guardrails in an A/B: proving impact
  11. Thumbs-down, escalation, resolution rate: production
  12. Kappa ≥ 0.7, judge agreement ≥ 80%: trusting the labels and judges

"For this design I'd track recall@5 for retrieval, groundedness for answers, and task success with argument accuracy for actions, gate releases on no slice regressing more than a point, and prove impact with an A/B test on one primary metric with latency, cost and safety as guardrails."

Testing and rollout gates

Metrics that decide whether a change ships.

MetricPlain meaningExample target
Golden-set regressionEvery metric vs the current version, per sliceNo slice down > 1 point
Blind side-by-side win rateExperts prefer new vs old, order hiddenWin or tie ≥ 95%
Shadow: judge win/tie, action agreementNew version on live traffic, outputs not shown≥ 95% win or tie; ≥ 95% same actions
Canary guardrailsErrors, p95, cost, thumbs-down at 1% → 5% → 25%Auto-rollback if errors > 2× or thumbs-down +30%
A/B primary metricOne business metric decided up frontSignificant lift (p < 0.05), sized in advance
A/B guardrailsMust not get worse: CSAT, latency, cost, safetyWithin tolerance

Escalation / handoff rateConversations passed to a humanDown, without CSAT dropping
Repeat contact / retry rateUser had to ask againDown
Acceptance / edit rateDrafts used as-is vs editedTrack; rising edits = quality drop

CSATSurvey satisfactionNot worse than baseline
Online eval scoresJudges run on 1 to 5% of real tracesStable vs offline numbers
Drift signalsTopic mix, score distribution, refusal rate changeAlert on shifts

Notes on the numbers

  • Targets are illustrative starting points. Set real ones from the current system's baseline and the cost of each mistake.
  • Report per slice (intent, language, customer tier), not only the average.
  • Use code for anything exact (amounts, ids, citations, schemas) and judges only for fuzzy qualities, calibrated against experts.
