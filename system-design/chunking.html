How to cut documents into passages that search well, cite cleanly and still make sense on their own.

What chunking is

Chunking cuts each document into passages small enough to search precisely and cheap enough to put in a prompt, while keeping enough context that each passage still makes sense on its own.

Every later step works on chunks: the embedding is computed per chunk, search returns chunks, citations point at chunks and the model reads chunks. So chunking quietly sets the ceiling for retrieval quality.

Try it: chunk a real policy

Below is a short leave policy with two countries, a table and repeated words like "adoptive parents". Change the strategy, size and overlap, and watch three things: chunks cut mid-sentence, the holiday table split in half, and whether the chunk holding the answer to "How many weeks do adoptive parents get in India?" still says it is about India.

Strategy

Two lessons usually jump out. Fixed-size cuts ignore the document's seams. And without a heading path, the India and US "adoptive parents" chunks look almost the same to search, so the system can confidently cite the wrong country.

Strategies compared

StrategyHow it cutsUse it forWatch out for
Fixed sizeEvery N tokens, optional overlapPlain text with no structure, quick baselinesCuts sentences, tables and code in half
RecursiveParagraphs, then sentences, then words, until it fitsA good general defaultStill blind to headings unless you add them
By heading / structureOne section per chunk, split further if too longWikis, policies, runbooks, docs with headingsVery long or very short sections; merge tiny ones
SemanticEmbeds sentences and cuts where the topic shiftsLong unstructured text such as transcriptsSlower ingestion; boundaries change when the model changes
Format-awareKeeps tables, code blocks and slides wholeSpreadsheets, code, decksLarge tables need row groups with the header repeated

Size and overlap

Small chunks give sharp matches but lose the words that say what they are about. Large chunks keep context but their embedding becomes an average of several ideas, so they match everything a little and nothing well. The 3D view shows why.

Defaults that hold up: 300 to 800 tokens, 10 to 20% overlap for fixed or recursive splitting, never bigger than the embedding model's input limit. Then measure.

Keep context with every chunk

  • Heading path header. Prefix each chunk with the document title and heading path before embedding. Cheap, and the biggest single win on structured documents.
  • Small-to-big. Index small child chunks for precise matching, and return their parent section to the model for context.
  • Contextual summaries. Ask a small model to write one sentence on where the chunk sits in the document, and prepend it. Costs one LLM call per chunk at ingestion.
  • Metadata, not just text. Store region, version and date as fields too, so a filter like region = India can do exact work that embeddings do loosely. Which fields, per source.

Metadata to attach, by source

Decide the metadata before you chunk, not after. The parser reads it from the source once per document, and every chunk of that document inherits it. Adding a field later means re-parsing everything.

Each field should earn its place by doing one of five jobs:

JobQuestion it answersTypical fields
FilteringWhich chunks are even eligible for this question?region, doc_type, product, language, status
FreshnessIs this the current version, and did it change?version, content_hash, updated_at, effective_from
DeletesWhich chunks go when the source item goes?doc_id, source, child IDs such as comment_ids
CitationsWhere exactly did this answer come from?url with anchor, section_path, page_start, line range
PermissionsWho is allowed to see this chunk?acl_groups, channel membership, audience

Three fields belong on every chunk whatever the source: a stable chunk_id built from doc_id plus version and position (so re-ingesting the same document overwrites instead of duplicating), the doc_id itself (so deletes are one call), and the ACL (so permissions are enforced in the query). The text field below is what gets embedded, with its heading-path header already added. The other fields are stored next to the vector and filtered on.

Policy and wiki pages

Chunk by heading. Most fields come from the page itself and are copied onto every chunk of it.

{
  "chunk_id": "wiki:leave-policy:v7:s3:c1",
  "doc_id": "wiki:leave-policy",
  "source": "confluence",
  "url": "https://wiki.example.com/hr/leave-policy#parental-leave",
  "title": "Leave policy",
  "section_path": ["Leave policy", "India", "Parental leave"],
  "chunk_index": 1,
  "text": "Leave policy › India › Parental leave\nAdoptive parents get 12 weeks of paid leave from the date the child is placed with them.",
  "version": 7,
  "content_hash": "sha256:9f2c…e41a",
  "updated_at": "2026-09-14T08:12:00Z",
  "effective_from": "2026-10-01",
  "region": "IN",
  "language": "en",
  "doc_type": "policy",
  "status": "published",
  "acl_groups": ["grp:all-employees-in", "grp:hr"],
  "owner_team": "people-ops"
}
FieldsWhy they matter
region, doc_type, languageFiltering. region = IN removes the near-identical US chunk before ranking, which embeddings alone do badly.
version, content_hash, updated_atFreshness. Skip re-embedding when the hash is unchanged, reject an older version arriving late, and prefer the newest page when two disagree.
effective_from, statusFreshness. A policy published today may not apply until next month; drafts and archived pages should never be retrieved.
doc_idDeletes. When the page is deleted or moved, remove every chunk with doc_id = wiki:leave-policy in one call.
url with anchor, section_pathCitations. Link straight to the section, and show the heading path so the reader can check it.
acl_groupsPermissions. Filter on the user's groups inside the search query, before the top k are chosen. See Access control.

Tickets with comments

A ticket is a description plus a thread. Chunk the description on its own, then group comments in time order, so a chunk never mixes the problem with an unrelated reply. Keep people as IDs, not names.

{
  "chunk_id": "jira:PAY-4821:comments:2",
  "doc_id": "jira:PAY-4821",
  "source": "jira",
  "url": "https://tickets.example.com/browse/PAY-4821?focusedCommentId=88213",
  "chunk_kind": "comment_group",
  "comment_ids": [88207, 88213],
  "text": "PAY-4821 · Refunds fail for cards issued in EU · Comments\n[2026-10-02] Root cause: the refund call sends the amount in cents, the EU gateway expects decimal units.\n[2026-10-03] Fixed in release 4.18.2. Retried refunds now succeed.",
  "project": "PAY",
  "issue_type": "bug",
  "status": "resolved",
  "resolution": "fixed",
  "priority": "P1",
  "components": ["refunds", "eu-gateway"],
  "labels": ["incident"],
  "fix_version": "4.18.2",
  "linked_issues": ["INC-311"],
  "author_ids": ["u_1842", "u_0977"],
  "created_at": "2026-10-01T10:40:00Z",
  "last_comment_at": "2026-10-03T16:05:00Z",
  "updated_at": "2026-10-03T16:05:00Z",
  "acl_groups": ["proj:PAY:browse"]
}
FieldsWhy they matter
status, resolutionFiltering. "How was this fixed?" should rank resolved tickets first; an open ticket only describes the problem.
project, components, issue_type, fix_versionFiltering. Narrow to one team or one release without trusting the embedding to notice the ticket key.
comment_ids, chunk_kindDeletes and edits. A deleted or edited comment rebuilds only its group, not the whole ticket.
updated_at, last_comment_atFreshness. A ticket reopened yesterday beats the same ticket's month-old resolution.
url with comment anchorCitations. The answer can point to the exact comment that holds the fix.
acl_groups, author_idsPermissions and privacy. Mirror project permissions; store author IDs so names stay out of the index and can be resolved at display time.

Code and API reference

Split on functions, classes and endpoints, never on line counts. The file path and symbol name do most of the work.

{
  "chunk_id": "git:payments-svc@3a9f1c2:src/refunds/client.py#RefundClient.create",
  "doc_id": "git:payments-svc:src/refunds/client.py",
  "source": "github",
  "repo": "payments-svc",
  "branch": "main",
  "commit_sha": "3a9f1c2",
  "path": "src/refunds/client.py",
  "language": "python",
  "symbol": "RefundClient.create",
  "symbol_kind": "method",
  "signature": "def create(self, payment_id: str, amount: Decimal, reason: str | None = None) -> Refund",
  "start_line": 48,
  "end_line": 91,
  "url": "https://git.example.com/payments-svc/blob/3a9f1c2/src/refunds/client.py#L48-L91",
  "text": "payments-svc · src/refunds/client.py · RefundClient.create\ndef create(self, payment_id: str, amount: Decimal, reason: str | None = None) -> Refund:\n    \"\"\"Create a refund. amount is in major units (e.g. 12.50), not cents.\"\"\"\n    ...",
  "imports": ["decimal.Decimal", "refunds.models.Refund"],
  "api_version": "v2",
  "deprecated": false,
  "updated_at": "2026-10-03T15:20:00Z",
  "acl_groups": ["repo:payments-svc:read"]
}
FieldsWhy they matter
repo, path, language, symbolFiltering and exact match. Keyword search on RefundClient.create finds what embeddings blur; see Search types.
commit_sha, branchFreshness. Index the default branch at a known commit; when it moves, re-embed only files whose hash changed.
api_version, deprecatedFiltering. Stop the model recommending a v1 endpoint that was removed last quarter.
doc_id = file pathDeletes. A deleted or renamed file removes all its symbol chunks in one call.
start_line, end_line, urlCitations. Link to the exact line range at that commit, which never changes underneath the link.
acl_groupsPermissions. Private repos must not leak into answers for people who cannot read them.

PDFs and manuals

Parse with a layout-aware parser, chunk by heading inside the PDF, and keep page numbers. People quote manuals by page.

{
  "chunk_id": "pdf:ac-x200-service-manual:r3:p42:c2",
  "doc_id": "pdf:ac-x200-service-manual",
  "source": "sharepoint",
  "file_name": "AC-X200_Service_Manual_rev3.pdf",
  "url": "https://files.example.com/manuals/AC-X200_Service_Manual_rev3.pdf#page=42",
  "title": "AC-X200 Service Manual",
  "revision": "rev3",
  "section_path": ["6 Troubleshooting", "6.4 Error codes"],
  "page_start": 42,
  "page_end": 43,
  "text": "AC-X200 Service Manual › 6 Troubleshooting › 6.4 Error codes\nE4: outdoor fan stalled. Switch off at the isolator, check the fan for obstruction, then measure the capacitor (expected 2.5 µF ±5%).",
  "contains_table": true,
  "figure_refs": ["Fig 6-3"],
  "product_models": ["AC-X200", "AC-X200P"],
  "language": "en",
  "ocr": false,
  "parser_confidence": 0.97,
  "published_at": "2025-11-30",
  "updated_at": "2026-02-11T09:00:00Z",
  "acl_groups": ["grp:field-service"]
}
FieldsWhy they matter
product_models, revision, languageFiltering. A technician on an AC-X200 must not get the AC-X100 fix, and rev2 instructions may be unsafe after rev3.
page_start, page_end, url with #pageCitations. "Page 42 of rev3" opens the PDF at the right page.
ocr, parser_confidenceQuality. Down-rank or flag chunks from poor scans instead of trusting garbled text.
contains_table, figure_refsAnswering. Tell the model a table or figure exists, so it says "see Fig 6-3" instead of inventing values.
doc_id, revisionDeletes and freshness. Uploading rev4 replaces every rev3 chunk under the same doc_id.

Chat and call transcripts

Chunk by thread or by time window (say 10 to 20 messages, or a few minutes of a call), with a small overlap. A single message is too short to mean anything on its own.

{
  "chunk_id": "slack:C04ONCALL:1727951412.0931:w1",
  "doc_id": "slack:C04ONCALL:1727951412.0931",
  "source": "slack",
  "url": "https://chat.example.com/archives/C04ONCALL/p1727951412093100",
  "channel_id": "C04ONCALL",
  "channel_name": "payments-oncall",
  "channel_type": "private",
  "thread_ts": "1727951412.0931",
  "message_ids": ["1727951412.0931", "1727951466.1022", "1727951530.4410", "1727951702.0087"],
  "window_start": "2026-10-03T10:30:12Z",
  "window_end": "2026-10-03T10:35:02Z",
  "text": "#payments-oncall · thread · 3 Oct 10:30–10:35 UTC\nu_1842: EU refunds failing again after deploy?\nu_0977: yes, same amount-format error as PAY-4821\nu_1842: rolling back to 4.18.1\nu_0977: rollback done, refunds recovering",
  "participant_ids": ["u_1842", "u_0977"],
  "mentions": ["PAY-4821"],
  "thread_resolved": true,
  "pii_redacted": true,
  "retention_expires_at": "2027-10-03T00:00:00Z",
  "acl_members_of": "C04ONCALL"
}
FieldsWhy they matter
channel_type, acl_members_ofPermissions. Private channel and DM content is visible only to members; check membership at query time.
window_start, window_endFreshness and filtering. "What happened during Tuesday's outage?" becomes a time-range filter.
message_idsDeletes. When a message is deleted or edited, rebuild the windows that contain it. Chat platforms send these events and you must honour them.
retention_expires_at, pii_redactedCompliance. A nightly job removes chunks past retention; redact before embedding, since vectors can leak the text they came from.
mentions, thread_resolvedLinking. Joins the chat to the ticket, and lets you prefer threads that reached an answer.

Tables and FAQs

Keep a small table whole. Split a big one into row groups and repeat the header in every chunk. For an FAQ, one question with its answer is one chunk, and you can embed the question on its own.

{
  "chunk_id": "sheet:shipping-rates:2026Q4:rows-11-20",
  "doc_id": "sheet:shipping-rates",
  "source": "google-sheets",
  "sheet": "Rates Q4 2026",
  "table_id": "standard-rates",
  "columns": ["Destination", "Weight band", "Standard", "Express"],
  "row_start": 11,
  "row_end": 20,
  "text": "Shipping rates Q4 2026 · Standard rates (rows 11–20)\nDestination | Weight band | Standard | Express\nGermany | 0–2 kg | €6.90 | €14.50\nGermany | 2–5 kg | €9.40 | €19.00\n…",
  "currency": "EUR",
  "valid_from": "2026-10-01",
  "valid_to": "2026-12-31",
  "updated_at": "2026-09-28T12:00:00Z",
  "acl_groups": ["grp:support", "grp:sales"]
}
{
  "chunk_id": "faq:billing:q-017",
  "doc_id": "faq:billing",
  "source": "help-center",
  "url": "https://help.example.com/billing#q-017",
  "faq_id": "q-017",
  "question": "Can I change my billing date?",
  "alt_questions": ["move payment date", "switch billing cycle day"],
  "text": "Q: Can I change my billing date?\nA: Yes, once per billing cycle, from Settings › Billing. The next invoice is pro-rated.",
  "category": "billing",
  "product": "all-plans",
  "audience": "customers",
  "updated_at": "2026-07-19T08:30:00Z",
  "acl_groups": ["public"]
}
FieldsWhy they matter
columns, row_start, row_endAnswering and citations. The header travels with every row group, and the citation names the rows used.
valid_from, valid_to, currencyFreshness. Last quarter's rates are still in the sheet history; filter on today's date to avoid quoting them.
question, alt_questionsMatching. Embed the question and its paraphrases separately and point them at one answer, since users ask questions, not answers.
audience, acl_groupsPermissions. An internal-only answer must never reach a public help bot.
faq_id, doc_idDeletes. Retiring one FAQ entry removes one chunk; deleting the sheet removes all its row groups.

Common mistakes

  • Putting filters only in the text. "Region: India" in the text helps the embedding a little; a region field filters exactly. Do both.
  • No doc_id on chunks. Then a deleted source document leaves orphan chunks that keep getting cited. Reconcile by comparing the source's ID list with the index's (a set difference) on a schedule.
  • ACLs checked after retrieval. If you take the top 8 and then drop the ones the user cannot see, they may get 1 result or none. Filter inside the search.
  • Too many unindexed fields. Only fields you filter on need a filter index in the vector database. Keep the rest as plain stored payload.
  • Names and secrets in metadata. Store user IDs and resolve names at display time; redact PII before it is embedded.

Tables, code and slides

  • Tables: keep small tables whole. Split big ones into row groups and repeat the header row in every group, or turn each row into a sentence ("Diwali: date varies").
  • Code: split on functions and classes, not on lines, and keep the file path in the header.
  • Slides: one slide per chunk, with the deck title and slide title as the header and speaker notes included.
  • Scanned PDFs: run layout-aware OCR first. Chunking cannot fix text that came out of the parser scrambled.

How to choose, with numbers

Do not guess. Build 100 to 200 golden questions with the chunk that answers each (see golden sets), then sweep a few settings and compare recall@k.

Setting (illustrative run)ChunksRecall@5Avg prompt tokens
Fixed 256, no overlap412k0.711,400
Fixed 512, 15% overlap240k0.782,900
By heading, max 800, with heading path205k0.863,300
Small-to-big (128 child, section parent)830k0.884,100

Illustrative numbers that show the usual pattern. Pick the cheapest setting within a point or two of the best recall, since prompt tokens are paid on every question.

Saying it in an interview

"I'd chunk by structure: one section per chunk, split recursively if a section passes about 800 tokens, keep tables whole with their header, and prefix every chunk with the title and heading path. I'd store region, version and ACLs as metadata for filtering. Then I'd tune size and overlap with a recall@k sweep on a golden set, and re-chunk from the stored parsed text, so it never needs another crawl of the sources."
