Search Types

Keyword, dense, hybrid and filtered search: how each matches, where each fails, and when to use which.

Keyword search

Keyword search tokenises text, builds an inverted index and scores with BM25. It is fast, explainable and unbeatable when the user types the exact thing they want.

Dense search

Dense search embeds the query and finds the nearest chunk vectors in a vector database. It shines when the user's words differ from the document's words: "baby leave" vs "parental leave policy".

Hybrid search and fusion

Run both searches in parallel (they are independent), take the top 50 or so from each, and fuse. RRF is the robust default. A weighted sum of normalised scores also works but needs tuning. Then send the fused list to a reranker.

When to use which

  • Enterprise documents with IDs, names and jargon: hybrid plus reranking.
  • Product catalogue or logs searched by codes: keyword first, dense as a fallback.
  • Support answers over conversational questions: dense or hybrid.
  • Anything with permissions: metadata filter applied inside every search, never after.

Query rewriting

Search quality often improves more from fixing the query than the index. Use a small model to turn a follow-up ("what about contractors?") into a standalone question, pull out filters (region = India), expand acronyms from a glossary, and sometimes generate two or three alternative phrasings to search in parallel.
