The map in one picture

Classic machine learning learns patterns from data instead of following hand-written rules. Two families cover almost every interview question: supervised (you have the right answers for past examples) and unsupervised (you do not).

Supervised learning

You have past examples with the correct answer (the label), and the model learns to predict that answer for new examples.

TypePredictsExamplesTypical models
RegressionA numberNext month's ad spend, delivery time, house priceLinear regression, gradient-boosted trees
ClassificationA categorySpam or not, will this user churn, which issue type is this reviewLogistic regression, random forest, gradient-boosted trees, fine-tuned text encoders

Features are the inputs (for churn: days since last login, plan, number of support tickets). Training means adjusting the model so its predictions match the labels on past data.

Prediction scores and thresholds

  • A classifier usually outputs a score, a probability such as "0.82 likely to churn", not just yes or no.
  • You turn the score into a decision with a threshold. Lower it to catch more cases (higher recall, more false alarms); raise it to be surer (higher precision, more misses).
  • Pick the threshold from the cost of each mistake: missing fraud is expensive, so a low threshold; auto-suspending an account is expensive when wrong, so a high one.
  • Scores also rank: "call the 1,000 customers most likely to churn" needs only the order.
  • The same score routes work in a cascade: confident cases decided automatically, uncertain ones sent to an LLM or a person.

Algorithms: trees and forests

ModelHow it works, in one lineStrengthsWatch out
Linear / logistic regressionA weighted sum of features (logistic squashes it into a probability)Fast, explainable: each weight says how a feature pushes the predictionMisses non-linear patterns and interactions
Decision treeA flowchart of yes/no questions on features ("tickets > 3?")Easy to explain, handles mixed dataOne deep tree memorises the training data (overfits)
Random forestHundreds of trees, each trained on a random sample of rows and features; they voteMuch less overfitting, strong default with little tuningLarger and slower than one tree; less explainable
Gradient-boosted trees (XGBoost, LightGBM)Trees built one after another, each fixing the previous ones' errorsUsually the most accurate on tabular dataMore tuning; can overfit if trained too long
Neural networks / fine-tuned encodersMany layers learning features themselvesBest for text, images, audioNeed more data and compute

Rule of thumb: tabular data → gradient-boosted trees or random forest; text at high volume with fixed labels → embeddings plus logistic regression, or a fine-tuned small encoder; open-ended text → an LLM.

Unsupervised learning

TaskWhat it doesCommon methodsExample
ClusteringGroups similar itemsk-means (you choose the number of groups), HDBSCAN (finds the number itself and leaves outliers out)Embed app reviews and cluster them to discover new complaint topics; customer segments
Anomaly detectionFlags items unlike the restIsolation forest, z-score on a metricSpike in crash reports, unusual ad spend, fraud
Dimensionality reductionCompresses many features into a fewPCA; embeddings are a learned versionVisualising data, speeding up other models

There are no labels, so judge results by usefulness: do the clusters make sense to a domain expert, are they stable when re-run, and do they lead to action? An LLM can name each cluster from a few examples.

Training basics

  • Train / validation / test split. Train on one part, tune on another, and report on a test set the model never saw. Split by time when predicting the future.
  • Overfitting means great on training data, poor on new data: the model memorised. Underfitting means poor on both: too simple.
  • Cross-validation: split the data into k parts, train k times, each time testing on a different part, and average. A more reliable score when data is small.
  • Regularisation: penalise complexity (smaller weights, shallower trees) to reduce overfitting.
  • Leakage: a feature that would not be known at prediction time (for churn, "account closed date") makes results look great offline and fail in production.
  • Class imbalance: when one class is rare (2% fraud), use class weights or resampling, and do not judge by accuracy.

Model evaluation

MetricPlain meaningUse for
PrecisionOf what I flagged, how much was rightWhen false alarms are costly
RecallOf what was really there, how much I caughtWhen misses are costly
F1 / macro-F1One score that is high only if both are high; macro averages per class so rare classes count equallyImbalanced classification
ROC curve and AUCHow well the scores separate positives from negatives across all thresholds. AUC 0.5 = random, 1.0 = perfectComparing models before choosing a threshold
PR curve / PR-AUCPrecision against recall across thresholdsBetter than ROC when positives are rare
MAE / RMSEAverage size of the error in regression (RMSE punishes big misses more)Predicting numbers
MAP / NDCGAre the relevant items near the top of a ranked listSearch, recommendations, retrieval

Always compare against a baseline (current rules, or "predict the most common class") and report results per slice (language, region, new vs existing users).

Labelling and cold start

  • Where labels come from: past human decisions, trained raters with written guidelines, user actions (clicked, refunded), or an LLM labelling a sample that humans spot-check.
  • Label quality: have two raters label the same items and measure agreement (Cohen's kappa; about 0.7 or more is good). Low agreement means unclear guidelines.
  • Active learning: send the items the model is least sure about to humans; their labels improve the model fastest.
  • Cold start: a new user, item or product has no history, so a history-based model has nothing to go on. Fall back to content features (the item's text, category), popular or rule-based defaults, or an LLM working zero-shot, and switch to the learned model as data builds up.

Monitoring: data drift and concept drift

  • Data drift: the inputs change (new languages, a new app version, a new customer segment). Detect by comparing feature distributions with training data.
  • Concept drift: the relationship itself changes, so the same input now means something else (after a pricing change, "too expensive" reviews mean something new; fraudsters change tactics). Detect by measuring performance on fresh labelled samples.
  • Watch the score distribution and the share above threshold; a sudden shift is an early warning before labels arrive.
  • Retrain on a schedule or when drift alerts fire; check the new model on the golden set and roll it out like any release (shadow, canary).

Saying it in an interview

"Supervised learning predicts a label from past labelled examples: regression for numbers, classification for categories. On tabular data I'd start with gradient-boosted trees or a random forest, compare against a baseline on a held-out test set, and avoid overfitting with cross-validation. Classifiers give a score, and I choose the threshold from the cost of false alarms versus misses, checking precision, recall and ROC-AUC. Unsupervised learning finds structure without labels, like clustering reviews to discover new topics or flagging anomalies. In production I monitor data and concept drift and retrain when performance on fresh labels drops."
