Citations

A citation is a promise: this sentence came from that source. The model writes the promise. Your code checks it before anyone reads the answer.

See it in 3D: every sentence tethered to its source

1 · Why cite, and at what grain

An answer such as “Apple’s FY2023 operating margin was 29.8%” is only as useful as the reader’s ability to check it. Citations do four jobs:

  • Trust: the reader sees where a claim came from.
  • Verification: one click to the page, not a search through 90 pages.
  • Audit: months later you can replay which source backed which sentence.
  • Catching hallucination: a sentence whose citation fails a check is the cheapest hallucination signal you will ever get.
Citations start at ingestion

You can only cite what you labelled. Each chunk needs a stable id and its source metadata (filing, accession number, section, page, table) stored when it is written, not reconstructed at answer time. If re-chunking changes the ids, every old citation breaks.

Lab: the same sentence, five grains

Pick a grain. The claim stays the same; what changes is how much a reader must read to check it, and what you had to store at ingestion.

Finer is not always better. A span or cell citation is easy to check but can hide context (the cell says 114,301, but is it in millions, and which fiscal year?). Show the span, and link to the page around it.

2 · Three ways to get citations out of a model

All three produce the same thing: answer text plus a pointer to a source for each claim. They differ in how much your code has to parse and trust.

Whichever way you choose, the model should cite while it writes, from the sources it was given. The alternative, post-hoc attribution, writes the answer first and then searches for sources that look similar. It nearly always finds something, and that is the problem: a chunk that shares words with a claim is not a chunk that supports it. Use post-hoc matching as a check on generated citations, not as their source.

Each check is a few lines of deterministic code, and together they cost microseconds:

# retrieved: {chunk_id: text}; calc: {call_id: output}. Sources the model may cite.
def verify(sentence, cites, quote, retrieved, calc):
    sources = {**retrieved, **calc}
    if not cites or any(c not in sources for c in cites):
        return "fail: cited id was not retrieved"          # invented id
    text = " ".join(sources[c] for c in cites)
    if norm(quote) not in norm(text):                      # or fuzzy, e.g. rapidfuzz partial_ratio ≥ 90
        return "fail: quote not found in source"
    for n in re.findall(r"\d[\d,]*\.?\d*%?", sentence):
        if n not in text:
            return f"fail: {n} not in the cited source"     # numbers must be copied, or come from a tool
    return "pass"

A fourth check needs a model: does the source entail the sentence? An NLI model or an LLM judge reads (source, sentence) and answers supported / contradicted / not enough information. It catches what string matching cannot, such as a quote that is real but a sentence that says the opposite. Run it on every answer if you can afford it, or on a sample plus every answer the cheap checks already flagged.

No source → don’t say it

When a sentence fails, don’t show it with a warning. Drop it, regenerate it, or say “the filing doesn’t state this”. In FinSight every number must come from either a cited chunk or a calculator tool output, which is why 29.8% cites calc-1 rather than the model’s own arithmetic.

4 · How citations fail, and how to measure them

failureexamplewhat catches it
Fabricated citationcites c77, which was never retrievedid check: exact, free
Right document, wrong claimcites the income statement for a number that is not on it (30.1%)number check, quote check
Citation laundering“operating margin improved [c41]”, while c41’s numbers show it fellonly entailment (NLI or judge)
Over-citingthree ids on a sentence that one supports, to look thoroughcitation precision
Post-hoc attributionanswer first, then the nearest-looking chunk is attachedgenerate with citations; entailment on a sample
Uncited claima sentence with no citation at all“every sentence cites” rule; unsupported-claim rate
Citation recallShare of answer sentences fully supported by their citations taken together (the ALCE benchmark’s definition, judged by an NLI model). Citation precisionShare of individual citations that actually support their sentence. Over-citing lowers it. FaithfulnessShare of the answer’s claims that can be inferred from the retrieved context (RAGAS, DeepEval). Groundedness in TruLens is the same idea. Unsupported-claim rateIn production: the share of sentences your verifier dropped or flagged. A rise after a prompt or model change is a regression alarm, no labels needed.

Citation metrics measure whether the answer is grounded, not whether it is right. A sentence can faithfully cite a wrong or out-of-date chunk. Keep answer-correctness evals (see ⑥ Testing & Evals and RAG evals) alongside them. And citations can only point at what retrieval found, so recall upstream (vector search, reranking) still sets the ceiling.

On screen, make checking cheap: hover a marker to see the exact span highlighted, click to open the filing at that page (an EDGAR document URL plus a page anchor), and keep the chunk id in the trace so an audit can replay it.

Remember
  • Stable chunk ids and source metadata are an ingestion decision.
  • The model may only cite ids it was given; check that in code.
  • Quotes and numbers must be found in the cited source, or come from a tool output.
  • Entailment catches the subtle failures; string checks catch the cheap ones.
Traps
  1. trusting the [n]: a citation marker is model output like any other
  2. post-hoc attribution as the main way to cite
  3. showing failed sentences with a warning instead of dropping them
  4. ids from list position (“doc 3”), which change when re-ranking does
